# Провенанс сборки скилла glavred

Аудиторский материал сборки: статистика конвейера, пороги и ограничения проверок. Агенту, применяющему скилл, этот файл не нужен — операционные соглашения полей описаны в самом SKILL.md, который лежит рядом.

Дата сборки — 2026-08-14. Скилл собран пайплайном book-to-skill (фазы 0–4: обзор источников → экстракция → валидация → сборка → эвалы).

## Статистика конвейера

Извлечено 1659 единиц; отброшено фильтрами 195; вычтено по охвату скилла 75; слито дубликатов 299; в улов фазы 2 вошло 1090.

Отбраковка ниже порога, который ставит конвейер сборки: он требует снять фильтрами не меньше трети кандидатов, снято 195 из 1659 — 11,8 %. Порог не набран, валидацию не перезапускали — решение принял пользователь на чекпойнте фазы 2. Счёт целиком: с вычетом по охвату 16,3 %, вместе со слиянием дубликатов 34,3 %, но слитый дубликат не отброшен, а поглощён с сохранением содержания, и в порог не засчитан.

В листы отобрано 184 номерованных правила плюс 81 кейс, отданный им в поле «Плохо → Хорошо», — 265 единиц из 1090. Отбор шёл по силе: число подтверждений в источнике, ярус, проверяемость правила на конкретном посте. По ярусам вошло 134 / 47 / 3 — но так считаются только правила, у которых стоит якорь; примеры взяты шире, 30 из них пришли не оттуда, где стоит якорь правила — 29 из другого источника, 1 из другого раздела того же источника, — и помечены в поле «Плохо → Хорошо» строкой «(пример — <источник>, раздел <…>)». С учётом примеров рассылка представлена заметнее, чем даёт счёт по якорям.

## Проверка полей примеров и оговорок

Строки «В источнике примера нет» и «В источнике оговорок нет» в листах поставлены по итогам сплошного прохода при сдаче: из 68 проверенных полей примера проход закрыл примером 30, ещё 2 отозвал в класс «конвертация вырезала эмодзи», 36 подтвердил чистыми; пропущенных оговорок закрыто 22 из 59.

Ограничения прохода — почему строки-заглушки не гарантия:

- решение по каждому полю выносил читающий агент; на повторных прогонах суждение расходилось примерно в одном случае из десяти (чаще всего на границе «оговорка к этому правилу или к соседнему»);
- окрестность якоря бралась в ±40 строк — что лежит дальше, проход не видел.

## Якоря и ограничение перепроверки

Каждая единица в листах несёт дословную цитату-якорь из источника и адрес раздела. Якоря проверены механическим поиском по файлам источников (сплошняком, без нормализации: неразрывные пробелы и разрывы переносов конвертации копируются побайтно).

Ограничение: полные тексты источников (локальные выгрузки) в репозиторий не входят — пока они живы локально, спорную единицу можно перепроверить по источнику; после их удаления перепроверять будет не по чему.

Рабочая сборка (каталог `pipeline/glavred/` в репозитории [Londeren/bookshelf-skills](https://github.com/Londeren/bookshelf-skills): карта источников, улов экстракции, валидация с причинами отбраковки, эвалы) опубликована вместе со скиллом. При доработке скилла недостающее поднимается оттуда.

## Переработка формы ответа (2026-09-29): версия 0.2.0

**Зачем.** Ответ ставил номер правила после каждой находки и правки («Правило 1.21, 1.23.») и называл источник словом «метод» без имени автора. У скилла hormozi та же форма дала документ, который почти не читался: номер правила примерно на каждые сорок слов. Причина была и в самом конвейере: шаблон правил выдачи в book-to-skill требовал объяснять «по правилу», а эвалы засчитывали номера в тексте.

**Что изменилось.** В book-to-skill 1.1.0 и 1.1.1 (репозиторий Londeren/claude-plugins, коммиты 97cb052 и 4aa6963) появился раздел о правилах выдачи собранного скилла. По нему одному отдельный сабагент на Opus переписал правила выдачи, список правок режима apply и ссылку на правило в абзаце о полях единицы. Теперь тело ответа несёт суть правила простыми словами, а номера стоят в блоке «Основания» в конце, по строке на находку или правку. Собственный совет помечается как «не Ильяхова». Оговорки применяются, а не пересказываются. Шаг на правиле из рассылки говорит об этом одной фразой. Запрос оснований открывает листы заново и цитирует правила дословно. Скилл получил проверку самого ответа перед выдачей: чеклист листа 05 проверяет пост, а не ответ. Ядро, роутинг, источники, листы и description не менялись.

**Проверка.** Эвал-набор не перепрогонялся: четвёртый assertion рерайт-кейсов и проход по выдуманным правилам рассчитаны на номера в тексте. Вместо этого прогнан смоук: два кейса набора, D-01 и R-02, на 0.1.2 и на новой версии, по одному прогону на каждую. Оценивали слепые грейдеры, блоки «Основания» вырезаны до оценки. Запись лежит в `pipeline/glavred/evals/2026-09-29-answer-shape/`.

| | 0.1.2 | новая |
|---|---|---|
| Номеров правил в теле (D-01, R-02) | 14, 19 | 0, 0 |
| Assertions | 9 из 9 | 9 из 9 |
| Правил, которых нет в листах | 0 | 0 |
| Строк блока, чьё правило подходит к шагу | не мерили | 25 из 25 |

Одна мелочь новой версии: рерайт R-02 заменил «более 500» на «больше 500» без правила и без пометки; факт от этого не изменился.

**Гейт.** Эвал-набор для 0.2.0 не перепрогонялся, его заменяет смоук выше. Пользователь принял этот waiver 2026-09-29, до слияния ветки в `main`.

**Что проверка не покрыла.**
- Два кейса, по одному прогону. Остальные кейсы набора, реальные посты и триггеры не перепрогонялись; description не менялся.
- Сверка по запросу на glavred не прогонялась. У hormozi она на том же разделе book-to-skill процитировала 16 фрагментов из 16 дословно.
- Пометка о рассылке поставлена только правилам с якорем в «Сильном тексте», ярус 3. «Большая книга о соцсетях», ярус 2, осталась без пометки по решению пользователя 2026-09-29: это книга, и из неё весь блок о формате поста.
- Assertions набора, которые требуют номера в тексте, не переписаны: этот файл — запись сборки 0.1.x.
